# From self-play to a batch

One model plays both sides of **B parallel games**. At every move, search produces
a policy target for each position. `jax.lax.scan` stacks those records along a new
time axis, producing arrays shaped `(T, B, …)`. The code immediately swaps these
axes to use the **(B, T) convention: B game rows × T time columns**, matching the
visualization and the returned rollout.

## Inside one move: `puct_policy`

Before a game takes an action, search explores possible futures. The caller
evaluates the root position and, during self-play, mixes in exploration noise.
`puct_policy` masks invalid root actions and builds one tree per game. It repeats
**select → expand → back up** for `num_simulations` simulations.

Play the walkthrough or use **Next** to inspect each phase. The model predictions
are illustrative; the scores and visit counts are computed from the tree.

<PuctDemo client:load />

Selection balances a normalized value estimate $\bar Q$ with an exploration bonus:

$$
\operatorname{score}(s,a) = \bar Q(s,a)
+ \left[1.25 + \log\frac{N(s)+19652+1}{19652}\right]
\frac{P(s,a)\sqrt{N(s)}}{1+N(s,a)}.
$$

Here $P$ is the prior probability, $N(s)$ counts node visits (including its initial
prediction), and $N(s,a)$ counts visits through an action. The implementation
normalizes Q using the parent value and visited sibling values; unvisited actions
have normalized value zero. A tiny random perturbation breaks score ties.

### Explore the policy score

`compute_policy_score(action_probs, node_visits, action_visits)` returns one
exploration bonus per action. Focus on one action below: increase its probability
to raise its bonus, or increase its visit count to reduce the bonus. More visits
to the node raise the shared exploration pressure through $\sqrt{N}$ and $c(N)$.
The surface maps node visits on X and action visits on Y; height and color show
the exploration bonus at the selected probability.

`simulate` follows `node_index → action → child_index` until it reaches an unexpanded edge or a finished node. `expand`
calls `transition_fn` to step the environment and evaluate that new position.
`backup` carries **reward + discount × child value** up the selected path.
For an ongoing alternating-turn game, discount is −1: the opponent's good position
is bad for the parent player. Terminal or truncated transitions use discount 0
and child value 0, so their immediate reward determines the backed-up return.

After search, root edge counts become `action_weights`, the policy training target.
Temperature changes only how `action` is sampled from those weights. With zero
simulations, the weights are uniform over legal actions; with no legal actions,
the fallback is uniform over all actions. The caller preserves finished games.

## Collect one time step at a time

Each iteration starts fresh games. For each of the `T = max_moves` scan steps:

1. Evaluate the current observations with the policy/value network.
2. Run MCTS with legal-action masking and root exploration noise.
3. Record the **pre-move** observation, search action weights, acting player, and
   `policy_mask = ~done`; advance each game with the selected action.

The next states become the scan's carry. Finished games stay finished: they are
preserved, not reset, and subsequent positions in their rows are padding.

## What the scan returns

`env_states` is the **final** batched state, with leaves shaped `(B, …)`. It is not a
history of states. The second return value contains the stacked records, which
are converted to batch-first order:

```python
# T = max_moves; B = num_envs; A = number of actions.
# *O = the environment's observation dimensions.
env_states, rollout = jax.lax.scan(
    step,
    env_states,
    (jax.random.split(play_key, config.max_moves),
     jnp.arange(config.max_moves, dtype=jnp.int32)),
)

def batch_first(x: jax.Array) -> jax.Array:  # (T, B, ...) -> (B, T, ...)
    return x.swapaxes(0, 1)

observation, action_weights, current_player, policy_mask = jax.tree.map(batch_first, rollout)
```

Every cell `[b, t]` lines up across the arrays and the figure.
A cell represents **one position**, not
one whole game. The action that ends a game still has a valid pre-move position;
only later time steps are masked.

## Attach the outcome after self-play

Once the scan ends, final rewards are looked up using each recorded player ID.
A win becomes `+1` for the winner's positions and `−1` for the opponent's positions.
Games still active at the move limit are adjudicated as draws with value target
`0`; a win on the final allowed move keeps its result.

The returned `Batch` contains `observation`, `action_weights`,
`value_targets`, `policy_mask`, and `value_mask`. The last three arrays
all have shape `(B, T)`. `current_player` is used to construct targets, then discarded.

Terminal padding trains neither head. Environment-truncated games keep their
valid policy positions but have **no value supervision**. This differs from a
move-limit draw, whose valid positions train both heads with value target zero.

## Sample positions from the rollout

The rollout keeps its `(B, T, …)` shape and is sharded across games. Sampling
flattens `policy_mask` to compute cumulative valid-position counts in game order:
all positions from game 0, then game 1, and so on. Flat index `b * T + t`
corresponds to cell `[b, t]`; padding occupies slots but is never selected.

`sample_batch` samples real positions uniformly **with replacement**, skipping
padding via `policy_mask`. It converts each sampled flat index back to `[b, t]`
and gathers all fields at those coordinates, returning `(M, …)` arrays where
`M = batch_size`. Each iteration performs `updates_per_iteration`
parameter updates using minibatches of size `batch_size` from this rollout.
There is no persistent replay buffer here.
